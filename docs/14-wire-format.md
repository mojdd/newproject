# 14 — تنسيق الرزمة (Wire Format)

تعريف بنية البايتات للرزمة اللي تنتقل بالـ mesh. هدفه: **مدمج (compact)** لأن BLE
محدود، **قابل للتوسعة** عبر إصدار، و**يفصل الـ header (للتوجيه) عن الحمولة المشفّرة
(للمحتوى)** عشان الوسطاء يوجّهون بلا ما يقرون.

> هذا تصميم مرجعي قابل للضبط أثناء التنفيذ (M2/M4). الأرقام مبدئية.

---

## مبادئ

- **Little-endian**، حقول ثابتة الطول قدر الإمكان.
- **Header مكشوف** (يحتاجه كل relay للتوجيه) + **Body مشفّر** (للمستلم فقط).
- **Signature** تغطّي (Header ما عدا `ttlHops` المتغيّر + Body) — عشان التعديل
  أثناء التمرير يُكشَف، بينما `ttlHops` يُسمَح يتغيّر.

> **لماذا `ttlHops` خارج التوقيع:** كل relay يُنقِص TTL، فلو كان ضمن التوقيع
> لانكسر. الباقي (المحتوى، المصدر، الهدف، المعرّف) موقّع ومحمي ضد العبث.

---

## بنية الرزمة

```
┌──────────────────────── HEADER (مكشوف) ────────────────────────┐
│ offset  size  field                                            │
│ 0       1     version          (تنسيق الرزمة، يبدأ 0x01)        │
│ 1       1     type             (0=BROADCAST 1=UNICAST 2=RECEIPT)│
│ 2       1     priority         (0=NORMAL 1=EMERGENCY)           │
│ 3       1     ttlHops          (يُنقَص كل قفزة — خارج التوقيع)   │
│ 4       16    messageId        (هاش فريد — dedup)               │
│ 20      16    originNodeId     (المصدر)                         │
│ 36      16    destNodeId       (الهدف؛ أصفار للـ broadcast)     │
│ 52      8     createdAt        (epoch millis)                   │
│ 60      2     bodyLen          (طول الـ body)                   │
├──────────────────────── BODY (مشفّر للـ unicast) ──────────────┤
│ 62      N     body             (sealed box ciphertext أو plain) │
├──────────────────────── SIGNATURE ────────────────────────────┤
│ 62+N    64    signature        (Ed25519 على header*+body)      │
└────────────────────────────────────────────────────────────────┘
header* = كل الـ header ما عدا البايت 3 (ttlHops) يُعامَل كصفر بالتوقيع/التحقق.
```

- **BROADCAST:** `body` = plaintext تجميعي (مكشوف للكل).
- **UNICAST:** `body` = `crypto_box_seal` لمفتاح `destNode` العام → relay ما يقرأ.
- **RECEIPT:** `body` = `messageId` المؤكَّد + نوع التأكيد؛ موقّع من المؤكِّد؛
  `destNode` = المصدر الأصلي (يفيض رجوعاً).

---

## التجزئة (Fragmentation)

لو طول الرزمة الكلي > (MTU − overhead)، تُقسَّم ([وحش ٦](06-wolf-ble-transport.md)):

```
┌──────────── FRAGMENT ────────────┐
│ 0   16   packetId   (= messageId)│
│ 16  2    fragIndex                │
│ 18  2    fragTotal                │
│ 20  N    chunk                    │
└───────────────────────────────────┘
```

المستقبل يجمّع حسب `packetId` لمن تكتمل `fragTotal`؛ timeout يُسقِط الناقص.

---

## الإصدار والتوسعة

- `version` بالبايت 0 يخلّينا نطوّر التنسيق مع توافق خلفي.
- إضافة حقول مستقبلية: عبر `version` جديد أو TLV اختياري بعد الـ body (قبل
  signature) — يُحدَّد عند الحاجة.

---

## حالات اختبار (JVM)

- [ ] encode→decode يرجّع نفس الحقول لكل الأنواع.
- [ ] تغيير `ttlHops` فقط **ما يكسر** التوقيع (محسوب كصفر).
- [ ] تغيير أي حقل آخر أو الـ body **يكسر** التوقيع.
- [ ] `bodyLen` غير مطابق → فشل فك مضبوط (ما crash).
- [ ] split/reassemble لرزمة > MTU بأطوال حدّية.
