# 🪨 وحش ٣ — التخزين-والتمرير + تأكيد التسليم (Store-and-Forward + Delivery)

## المشكلة

ماكو سيرفر يگلك «وصلت». فكيف تعرف، وأنت بلا نت، إن رسالتك وصلت للهدف؟

اختبار النجاح: **دورة ⏳ → ✓ تشتغل كاملة أوفلاين** (المصدر يستلم خبر الوصول عبر
الـ mesh بلا أي نت).

---

## ١. آلة الحالة (State Machine)

```
QUEUED_LOCAL ──> IN_MESH ──┬──> DELIVERED_PEER   (وصلت العقدة الموثوقة الهدف)
                            └──> UPLOADED_SERVER  (ارتفعت لبوابة → سيرفر)
                                       │
                                       ▼
                                     ACKED         (رجع إيصال للمصدر)
                                       │
                                       ▼
                                     EXPIRED        (انتهى عمرها أو وصل ACK)
```

| الحالة | المعنى | مؤشر المستخدم |
|--------|--------|----------------|
| `QUEUED_LOCAL` | مخزونة محلياً، ما دخلت الشبكة بعد | ⏳ |
| `IN_MESH` | تُفاض حالياً بالـ mesh | ⏳ |
| `DELIVERED_PEER` | استلمها الهدف الموثوق | ✓ (محلي) |
| `UPLOADED_SERVER` | رفعتها بوابة للسيرفر | ✓ (سيرفر) |
| `ACKED` | رجع إيصال للمصدر | ✓✓ مؤكّد |
| `EXPIRED` | انتهت — تتوقف عن الانتشار | — |

## ٢. التخزين والتمرير

- كل رزمة **تُخزَّن محلياً** (Room، [وحش ٧](07-wolf-storage.md)) وتبقى تُمرَّر حتى
  تُسلَّم أو تنتهي.
- العقدة تعيد بثّ الرزم المخزونة دورياً (مو مرة وحدة) — لأن الجيران يتغيرون؛
  جار جديد قد يحملها أبعد.

## ٣. الانتهاء الزمني (Expiry)

- بعد **٢٤–٤٨ ساعة** أو بعد وصول **ACK**، الرزمة:
  - تتوقف عن الانتشار.
  - تُشطَّب من طابور التمرير.
- يمنع تراكم الرزم القديمة ونزف الذاكرة/البطارية.

## ٤. الإيصالات (Receipts) ترجع بالـ mesh

- لمن يستلم **الهدف** الرزمة (أو **السيرفر** عبر بوابة)، يُولَّد **ACK** ويُفاض
  **رجوعاً نحو المصدر** — الـ `originNodeId` معروف بالـ header.
- فحتى لو المصدر **بلا نت**، يوصله خبر «وصلت» عبر الشبكة.
- الإيصال نفسه رزمة من نوع `Receipt` ([وحش ٢](02-wolf-routing.md)) — يخضع لنفس
  TTL/dedup/suppression، لكن وجهته `originNodeId`.
- الإيصال **موقّع** بمفتاح الهدف/السيرفر عشان المصدر يتأكد إنه أصلي مو مزوّر
  ([وحش ٤](04-wolf-crypto-identity.md)).

## ٥. سيناريو السيارة بالسيطرة (مثال متكامل)

```
1. زائر يرسل رسالة لموثوق بعيد → QUEUED_LOCAL ثم IN_MESH (تنطّ بين التلفونات).
2. سيارة تفوت بسيطرة فيها تغطية → عقدتها تلمس نت → تصير بوابة (وحش ٥).
3. البوابة ترفع: المخزون التجميعي + الرزم الشخصية المشفّرة (blobs) للسيرفر.
4. السيرفر يخزّن/يمرّر، يردّ ACKs → الرزمة UPLOADED_SERVER ثم ACKED.
5. الإيصالات تفيض رجوعاً بالـ mesh نحو المصادر → الناس تطمّن بلا ما تلمس نت.
```

## ٦. واجهة مقترحة (منطق نقي + مستودع)

```kotlin
interface ForwardingStore {
    suspend fun enqueue(packet: Packet)                 // QUEUED_LOCAL
    suspend fun markState(id: MessageId, s: MsgState)
    suspend fun dueForRebroadcast(now: Long): List<Packet>
    suspend fun onReceiptReceived(receipt: Receipt)     // يطابق ويصعّد الحالة
    suspend fun reapExpired(now: Long): Int             // EXPIRED + شطب
    fun observe(id: MessageId): Flow<MsgState>          // للـ UI
}
```

> آلة الحالة والمطابقة وقواعد الـ expiry **منطق نقي قابل لاختبار JVM**. فقط
> الـ persistence (Room/SQLCipher) أندرويد.

## ٧. حالات اختبار

- [ ] رزمة جديدة → `QUEUED_LOCAL`.
- [ ] استلام receipt مطابق → الحالة تصعد لـ `ACKED` ويتوقف الانتشار.
- [ ] رزمة تجاوزت 48h بلا ACK → `EXPIRED` وتُشطَّب من طابور التمرير.
- [ ] receipt بتوقيع غير صالح → يُهمَل (ما يغيّر الحالة).
- [ ] `dueForRebroadcast` يرجّع فقط الرزم غير المنتهية وغير المؤكّدة.
