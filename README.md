# شبكة الأربعينية — تطبيق تواصل الزوار عبر Mesh

تطبيق Android يخلّي **ملايين زوار الأربعينية** يتواصلون ويتشاركون معلومات خدمية
**بدون اعتماد على الإنترنت**. كل تلفون يصير **عقدة (node) بشبكة mesh**: يحجي مع
التلفونات اللي حوله مباشرة عبر BLE/Wi-Fi، والرسالة **تنطّ من تلفون لتلفون** حتى
توصل بعيد بلا أي برج اتصال. ولمن **أي عقدة تلمس نت**، تصير **بوابة (gateway)** ترفع
البيانات المسموحة فقط لسيرفر حكومي.

> **الفكرة الجوهرية:** الـ mesh يعتمد على **الكثافة** — كل ما زاد عدد الناس
> القريبين، اشتغلت الشبكة أحسن. والأربعينية من أكثف التجمعات بالعالم، فهي بيئة
> مثالية لهذا النوع من الشبكات.

---

## ⚠️ حالة المشروع (الصدق أولاً)

**ماكو كود بعد — هذا توثيق تصميم فقط.** السبب: البيئة السحابية الحالية ما تكدر
تبني تطبيق Android حقيقي:

- ⛔ ماكو **Android SDK**، و `dl.google.com` محجوب → ما نكدر ننزّله.
- ⛔ `maven.google.com` محجوب → Android Gradle Plugin وكل مكتبات
  AndroidX/Compose/Room غير قابلة للوصول.
- ⛔ ماكو **أجهزة Android حقيقية** — و M1/M6 (الخلفية + BLE) ما تنختبر على
  محاكي أصلاً.

التفاصيل الكاملة بالقيود وخطة التنفيذ بالبيئة الصحيحة:
[`docs/13-environment-and-status.md`](docs/13-environment-and-status.md).

هذي الوثائق مكتوبة لتكون **spec قابل للتنفيذ مباشرة** لمن تتوفّر بيئة فيها SDK
وأجهزة.

## المبادئ الحاكمة (لا تُتجاوز)

1. **أوفلاين أولاً** بكل سطر — ولا شي ينتظر سيرفر.
2. **التوقّف الأمين** — إذا نظام ما يشتغل، قُل "ما يشتغل بعد"؛ لا تخفي فشل تحت كود
   يبيّن شغّال.
3. **الخطوط الحمراء ([وثيقة 10](docs/10-red-lines.md)) مطلقة** — لا تُبنى تحت أي
   ظرف. المبدأ: رقم عن **مكان/خدمة/موكب** مسموح ✅، عن **إنسان فرد** ممنوع ⛔.
4. **الأنظمة القاتلة أول** — لا تُبنى الميزات قبل البنية ([وثيقة 11](docs/11-build-plan.md)).
5. كل milestone **يُبنى ويشتغل** قبل التالي.
